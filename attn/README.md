# attn

複数の AI エージェント（Claude Code、Codex）のセッションのうち、**あなたを待っているもの**を1か所に集めて見せる。
エージェントを起動したり操ったりはしない。今どれが止まっていて、何を頼み、どこまで進んだかが分かれば、見て回る切り替えが減る、という考えで作っている。

背景と、ほかのツールとの比べ方は [調査メモ](../docs/attn-research.md) を参照。

## できること

- 直近24時間に動いたセッションを、次の状態に分けて一覧にする（ブラウザと端末）。

  | 状態 | 意味 |
  | --- | --- |
  | 承認待ち | ツールの実行やプランの承認を待っている |
  | 質問・入力待ち | エージェントが質問している（AskUserQuestion など） |
  | 動きなし | 考え中やツールの実行中のまま、ログが動いていない。承認待ちか、止まっている |
  | あなたの番 | 応答を返し終えた。まだ確認していない |
  | 作業中 | 動いている |
  | 確認済み | 確認済みにしたもの、または12時間以上前に終わったもの |

- セッションごとに「目的 / 依頼 / 結果 / あなたへ」の4行を出す。戻る前に読めば、ログを読み返さずに済む（下の「応答の先頭の4行」）。4行がない応答は「頼んだこと（最後の指示）」と「最後の報告」を出す。報告に PR・MR の URL があればリンクにする。
- 「あなたの番」は、あなたにしてほしいことの急ぐ順（作業 → 回答 → 判断 → 確認 → なし）に並べる。「なし」は読むだけでよいので最後に回る。
- 承認待ち・質問・動きなしになったら、macOS の通知ですぐ知らせる。「あなたの番」は30分ごとにまとめて知らせる（作業を細かく中断されないように）。
- 進行中（作業中＋動きなし）が上限（既定3）を超えたら赤く表示する。
- 再開コマンド（`claude --resume <id>` など）をコピーできる。

## 使い方

Node.js 22 以上。依存パッケージはない。

```sh
cd attn
node bin/attn.js serve          # http://127.0.0.1:7878/ を開く
node bin/attn.js list           # 端末で今の状態を見る
```

| オプション | 既定 | 内容 |
| --- | --- | --- |
| `--port` | 7878 | 画面のポート |
| `--hours` | 24 | この時間内に動いたセッションだけを出す |
| `--wip` | 3 | 進行中の上限（超えたら赤く表示） |
| `--digest` | 30 | 「あなたの番」をまとめて通知する間隔（分）。0 で通知しない |
| `--no-notify` | | 通知を出さない |

| 環境変数 | 既定 | 内容 |
| --- | --- | --- |
| `ATTN_IGNORE` | `/tmp,/private/tmp` | このパスで始まる場所のセッションを出さない（カンマ区切り） |
| `ATTN_STATE_DIR` | `~/.local/state/attn` | フックのイベントと確認済みの印の置き場 |

### 応答の先頭の4行

エージェントに、作業をした応答の先頭へ次の4行を書かせると、attn がそれを読み取ってカードの見出しにする。
`~/.claude/CLAUDE.md`（Codex なら `~/.codex/AGENTS.md`）に、書式を決める指示を入れておく。

```
**目的**: このセッションで達成したいこと
**依頼**: 今回頼まれたこと
**結果**: 完了 / 一部完了 / 未完了 / 失敗 のどれかで始め、どうなったか
**あなたへ**: [なし / 確認 / 判断 / 回答 / 作業] のどれか1つで始め、してほしいこと
```

| あなたへ | 意味 |
| --- | --- |
| 作業 | 人にしかできない操作（ログイン、本番の承認、購入など） |
| 回答 | 質問に答えてほしい |
| 判断 | 選択肢から選んでほしい |
| 確認 | 成果物を見てほしい（PR のレビューなど） |
| なし | 読むだけでよい |

太字の有無、全角のコロン、引用（`>`）や箇条書き（`-`）の記号は気にせず読む。見るのは応答の先頭30行だけ。

### フックを入れる（任意）

フックがなくても、ログ（`~/.claude/projects/` と `~/.codex/sessions/`）から状態を推定する。
ただしログだけでは「ツールの承認待ち」と「長いコマンドの実行中」を見分けられず、90秒たってから「動きなし」になる。
Claude Code のフックを入れると、承認待ちがすぐ正確に分かる。

```sh
node bin/attn.js hooks              # 足す設定を表示する
node bin/attn.js hooks --install    # ~/.claude/settings.json に足す（元の設定は settings.json.bak-attn）
node bin/attn.js hooks --uninstall  # 外す
```

使うフックは `UserPromptSubmit`、`PermissionRequest`、`Notification`、`Stop` の4つ。フックは受け取ったイベントの種類・時刻・セッション ID・ツール名だけを `events.jsonl` に書き、標準出力には何も出さない。失敗しても Claude Code の動きは止めない。

## 仕組み

```
~/.claude/projects/*/*.jsonl ─┐ ログの末尾（512KB）を読み、最後に何が起きたかで状態を推定
~/.codex/sessions/Y/M/D/*.jsonl┤
Claude Code のフック ──────────┘ events.jsonl に追記。ログより新しければフックの状態を優先
        ▼
attn serve（127.0.0.1 だけで待ち受け、3秒ごとに読み直す）
  ├ GET /              画面
  ├ GET /api/sessions  一覧（JSON）
  ├ POST /api/ack      確認済みにする（同じオリジンからの JSON だけ受ける）
  └ macOS の通知（osascript）
```

- 画面と API は指示の本文を返すので、`127.0.0.1` だけで待ち受け、`Host` ヘッダーが `127.0.0.1` か `localhost` でないリクエストを断る（DNS リバインディング対策）。
- ログやイベントを外へ送らない。

## 分かっている制限

- `claude -p` などで自動で動かしたセッションは、ログの `entrypoint` が `sdk-cli` のものだけ除外する。T3 Code などの SDK の中から起動したものは対話のセッションと見分けられないため、`ATTN_IGNORE` で場所を指定して除外する。
- `SessionStart` と `SessionEnd` のフックは使わない。T3 Code ではターンごとにプロセスが起動・終了するようで（ログにプロセス終了時の `cost-state` が毎回ある）、「終わった」と「返事を待っている」を見分けられないため。
- Codex は、ログからの推定だけ（Codex の `notify` 設定はほかのツールが使っていることが多いので、触らない）。

## 今後やりたいこと

- 最後の報告を3行に要約する（「やったこと / あなたに求める判断」）。
- 「次にやらせたいこと」の待ち行列。進行中が上限を下回ったら知らせる。
- 1日の終わりのまとめ（完了したもの、PR、残っている作業）。
- launchd で常駐させる。
